# About this example

`2026-10-26.md` is what Daniel's scheduled task produced on the Monday the
chapter follows. Every person, task, client, and link in it is invented, and
the ClickUp, Slack, Gmail, and Calendar URLs do not resolve.

Use it as a target, not as a template to copy. Your own first digest should
differ in content and match in shape.

## Reading it against the instructions

| Instruction | Where you see it in the file |
|---|---|
| 3-sentence summary of the week ahead | the paragraph under the title |
| One section per priority level | the five numbered headings, in the instructed order |
| Links back to the source items | every bullet |
| Workload note per team member | the last line |
| Skip list | no newsletters, no resolved threads, no empty calendar holds |
| Under one page | about 315 words, which prints to roughly two thirds of a page |

## The two things a good digest does that a list does not

The Tuesday meeting entry says which unanswered questions will come up in it.
The vendor email entry says which blocked task it unblocks. Those cross
references are what make the digest a starting point for the week rather than
four filtered lists stacked on top of each other, and Claude produces them
because the instructions order by urgency rather than by source.
