# SOP-XXX: [Title]

**Purpose:** what this procedure achieves, in one sentence
**Owner:** the role accountable for this process (role name, never a person's name)
**Trigger:** the event that starts it, and how the team finds out about it
**Frequency:** how often it typically runs
**Tools:** software, templates, and accounts involved, with locations
**Time:** typical duration from trigger to done
**Last updated:** YYYY-MM-DD, one line describing what changed
**Last reviewed:** YYYY-MM-DD, the date an owner last confirmed the content still matches reality

## Roles

One line per role: the role name and what it is responsible for inside this procedure. Use role names (for example "operations lead"), never personal names, so the document survives staff changes.

## Steps

Numbered list. One action per step, starting with a verb, small enough to check off. Name exact buttons, fields, folders, and templates. Five to fifteen steps is a useful range rather than a rule: below five, the procedure is often a section of a larger one, and above fifteen, check whether a second process has crept in. If it has, split it out and reference it ("complete the software setup by following SOP-XXX").

## Decision points

Every fork appears twice. The numbered step names the condition and says where to go; this section states the condition and the path for each outcome in full, so a reader can look up the fork without reading the procedure from the top.

- **If [condition]:** do X (or follow steps Na to Nd)
- **If not:** continue at step N

## Edge cases

Each edge case is a symptom and a response:

- **Symptom:** what you observe when this exception happens
- **Response:** what to do, including which template to use and when to escalate

## Done means

The observable finished state, and who checks it. Without it, the person running the procedure has no way to know they are finished.

---

Unresolved items stay visible as **[TO CONFIRM: ...]**. Conflicting team input stays visible as **[OWNER DECISION: ...]** until the owner resolves it, and the resolution goes into the document with one sentence of reasoning.
